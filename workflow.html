Рабочий процесс в системах контроля версий

Понимание типичных рабочих процессов помогает эффективно использовать Git и SVN в команде.

Базовый цикл работы в Git

  1. Изменение файлов — вы редактируете код в рабочей директории
  2. Индексация (git add) — выбираете, какие изменения попадут в коммит
  3. Коммит (git commit) — фиксируете изменения в локальном репозитории
  4. Отправка (git push) — передаёте коммиты на удалённый сервер
  5. Получение (git pull) — забираете изменения от коллег

Ветвление в Git

Одно из главных преимуществ Git — дешёвое ветвление. Типичные сценарии:

  • Feature branch — отдельная ветка под каждую новую функцию
  • Release branch — ветка для стабилизации релиза
  • Hotfix branch — ветка для срочных исправлений

Разрешение конфликтов

Конфликты возникают, когда два разработчика изменили одну и ту же строку. Что делать:

  1. Открыть файл с конфликтом — Git вставит маркеры <<<<<<<, =======, >>>>>>>
  2. Выбрать нужный вариант (или объединить оба)
  3. Удалить маркеры конфликта
  4. Добавить файл: git add FILE
  5. Завершить слияние: git commit

Рабочий процесс в SVN

  1. Update — получить свежие изменения с сервера
  2. Edit — работать с файлами
  3. Commit — отправить изменения на сервер
  4. При конфликте — обновить, разрешить, закоммитить

Рекомендации

  • Делайте небольшие коммиты с осмысленными сообщениями
  • Пишите сообщения в повелительном наклонении: «Add login form»
  • Не коммитьте пароли, ключи и большие бинарные файлы
  • Перед push всегда делайте pull
