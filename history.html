История систем контроля версий

Системы контроля версий прошли долгий путь развития — от простых локальных решений до распределённых систем, которые используются миллионами разработчиков по всему миру.

Хронология развития

1972 — SCCS

Source Code Control System — первая система контроля версий, разработанная в Bell Labs. Работала только с текстовыми файлами и хранила дельты изменений.

1982 — RCS

Revision Control System — сменила SCCS, добавила блокировку файлов для предотвращения одновременного редактирования.

1986 — CVS

Concurrent Versions System — первая система с клиент-серверной архитектурой. Позволила работать нескольким разработчикам одновременно.

2000 — SVN (Subversion)

Subversion создана компанией CollabNet как замена CVS. Исправила многие недостатки предшественника: атомарные коммиты, версионирование каталогов, эффективное ветвление.

2005 — Git

Линус Торвальдс создал Git для разработки ядра Linux после конфликта с правообладателями BitKeeper. Git стал первой массовой распределённой VCS.

2005 — Mercurial

Ещё одна распределённая система, созданная почти одновременно с Git. Отличается более простым и понятным интерфейсом.

2008 — GitHub

Запуск платформы GitHub сделал Git массовым. Хостинг репозиториев, социальные функции и pull requests изменили open source-разработку.

2020-е — наши дни

Git доминирует в индустрии. SVN используется в основном в унаследованных корпоративных проектах. Появляются новые инструменты поверх Git — например, Jujutsu.

Ключевые вехи

  1. 1972: первая VCS — SCCS
  2. 1986: клиент-серверная модель — CVS
  3. 2000: атомарные коммиты — SVN
  4. 2005: распределённая модель — Git
  5. 2008: массовость — GitHub
